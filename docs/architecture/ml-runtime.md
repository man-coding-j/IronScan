# On-device ML runtime

IronScan uses direct Core ML generated model classes. `ModelRegistryActor` validates and loads each model once for a selected compute-unit policy. `SegmentationInferenceActor` and `RiskInferenceActor` serialize native predictions and never execute on `MainActor`.

## Contract

The manifests are the locked source of truth for package SHA-256, feature names and shapes, BGRA/sRGB input, vImage resize behavior, model-embedded normalization, outputs, thresholds, and preprocessing versions. Package SHA-256 is calculated by hashing each package file in sorted relative-path order as `path + NUL + bytes + NUL`.

The engineering fixture models are deterministic plumbing models generated by `IronScanTests/ML/Fixtures/generate_fixture_models.py`. They are not trained screening models. `RiskInferenceActor` therefore returns `unableToAssess` for these packages even when a score is produced for parity testing. Replace both packages and update their manifests, generator/parity fixtures, versions, and tests before any validated evaluation.

## Preprocessing

Inputs must be orientation-normalized 32BGRA buffers tagged by the caller as sRGB. `PixelBufferFactory` uses CPU vImage high-quality scaling with scale-fill because that method is locked in both manifests. It performs no color correction, automatic contrast, histogram equalization, or white balance. Core ML applies the manifest scale of `1/255` inside each model.

## Segmentation postprocessing

The runtime thresholds the probability mask, keeps the largest connected component, fills holes no larger than the manifest limit, performs binary closing, removes small components, erodes the boundary by the configured percentage, and reports area and confidence statistics.

## Cancellation and memory

Actors check cancellation before preprocessing and immediately before native prediction. Once synchronous Core ML prediction begins it runs to completion. Input buffers are copied before inference and are never mutated while Core ML owns them. Temporary-buffer counts are recorded around preprocessing allocations.

## Performance status

Model-load, preprocessing, segmentation, caller-supplied calibration, risk-inference, total-pipeline, and peak temporary-buffer metrics are recorded. Physical-device p95 values are not yet available. Record p95 results here for at least two supported iPhones before this task is considered complete.

## Parity tolerances

- Calibrated probability absolute difference: at most `0.01`.
- Locked fixture decision mismatches: none.
- Segmentation Dice against Python output: at least `0.99`.
- Preprocessing tensor/pixel tolerance: `0.0001` where floating-point conversion applies; BGRA byte preprocessing must match exactly.
