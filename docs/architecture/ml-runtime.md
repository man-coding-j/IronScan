# On-device ML runtime

IronScan uses direct Core ML generated model classes. During app startup, `ScanPipelineActor.prepareModels()` asks `ModelRegistryActor` to load and validate both packages. The registry retains one instance of each model for the selected compute-unit policy. `SegmentationInferenceActor` and `RiskInferenceActor` serialize native predictions and never execute on `MainActor`.

The live camera path sends every 24th BGRA preview frame to `SegmentationInferenceActor` for non-clinical alignment guidance. It never sends an uncalibrated preview frame to `RiskInferenceActor`. Live timing uses unified logging category `live-scan`, and the UI displays the same duration beside the alignment ring.

## Contract

The manifests are the locked source of truth for package SHA-256, feature names and shapes, BGRA/sRGB input, vImage resize behavior, model-embedded normalization, outputs, thresholds, and preprocessing versions. Package SHA-256 is calculated by hashing each package file in sorted relative-path order as `path + NUL + bytes + NUL`.

The engineering fixture models are deterministic plumbing models generated by `scripts/generate_fixture_models.py`. They are not trained screening models. `RiskInferenceActor` therefore returns `unableToAssess` for these packages even when a score is produced for parity testing. Replace both packages and update their manifests, generator/parity fixtures, versions, and tests before any validated evaluation.

## Preprocessing

Inputs must be orientation-normalized 32BGRA buffers tagged by the caller as sRGB. `PixelBufferFactory` uses CPU vImage high-quality scaling with scale-fill because that method is locked in both manifests. It performs no color correction, automatic contrast, histogram equalization, or white balance. Core ML applies the manifest scale of `1/255` inside each model.

Physical captures pass through `SmartColorCalibrationActor` after segmentation and before risk inference. The actor returns a manifest-versioned `CalibratedTongueSample`; `RiskInferenceActor` rejects unsuccessful calibration and preprocessing-version mismatches before loading or invoking the risk model. The locked default has no validated physical reference configuration, so current physical captures remain unable to assess.

## Segmentation postprocessing

The runtime thresholds the probability mask, keeps the largest connected component, fills holes no larger than the manifest limit, performs binary closing, removes small components, erodes the boundary by the configured percentage, and reports area and confidence statistics.

## Cancellation and memory

Actors check cancellation before preprocessing and immediately before native prediction. Once synchronous Core ML prediction begins it runs to completion. Input buffers are copied before inference and are never mutated while Core ML owns them. Temporary-buffer counts are recorded around preprocessing allocations.

## Parity tolerances

- Calibrated probability absolute difference: at most `0.01`.
- Locked fixture decision mismatches: none.
- Segmentation Dice against Python output: at least `0.99`.
- Preprocessing tensor/pixel tolerance: `0.0001` where floating-point conversion applies; BGRA byte preprocessing must match exactly.

## Training export

`MLTraining/scripts/train_and_convert.py` exports a fixed `224 × 224` RGB image input as a float32 ML Program and embeds the image-scale contract in Core ML metadata. Validation logits receive Platt probability calibration, and the locked threshold is selected on the validation split before one-time participant-grouped test evaluation. Newly trained packages remain `engineeringFixture` until independent validation and all Python/Swift parity gates are complete.

`MLTraining/scripts/train_pallor_model.py` separately exports `IronScanPallorClassifier.mlpackage` for visual-pallor integration experiments. It predicts the TongueDX `TonguePale` annotation, not anemia or iron status. `ModelRegistryActor` loads it once, and `LiveInferenceEngine` serializes predictions at no more than one per second after acceptable live segmentation. The engine preserves the manifest-locked full-frame `scaleFill` preprocessing rather than introducing an untrained central crop. SwiftUI presents only a clearly labeled engineering preview; the model must not drive `RiskPrediction` or participant-facing decisions. Its aggregate evaluation is recorded in `MLTraining/reports/pallor-v0.1.0/evaluation_summary.json`.

`MLTraining/scripts/train_multi_label_model.py` exports `IronScanMultiScreen.mlpackage` with five individually named calibrated probability outputs and per-output thresholds in `multi_screen_manifest.json`. `ModelRegistryActor` validates and loads the package once per process. `MultiInferenceEngine` serializes one direct Core ML prediction per second after acceptable segmentation and returns all five visual-annotation scores from the same prepared pixel buffer. `ResultTranslator` compares each score only with its manifest-locked threshold and produces short appearance-only descriptions without exposing probabilities. `HumanResultsView` presents those descriptions and explicitly avoids translating visual annotations into diseases, deficiencies, treatment advice, or clinical decisions. The package passes Python/Core ML probability parity and compiles for iOS 18.

`VisualRiskSummaryEngine` maps only an eligible, quality-accepted pallor output to `Lower observed risk` or `Possible anemia risk` using the manifest-locked threshold. Rejected image quality and invalid output values return `Unable to assess`. Debug builds explicitly enable `PrototypeDemoMode` after one-time research consent and retain concise research-prototype and laboratory-confirmation copy in the active flow; non-debug builds continue to reject engineering fixtures. User-initiated captures may bypass the one-second inference throttle but remain serialized by `MultiInferenceEngine`. The engine does not estimate hemoglobin, ferritin, iron status, or a numerical clinical-risk score. Optional biological-sex, diet-pattern, fatigue, and cold-hands context is retained locally through app-scoped preferences, displayed separately, and never supplied to Core ML or the visual-summary calculation.

`IronHealthInsightsBuilder` selects general educational cards after the visual category is finalized; it does not modify model scores or decisions. Plant-based diet context may display NIH-sourced information about non-heme iron and vitamin C. A possible-risk category may display MedlinePlus-sourced information about CBC and ferritin testing without claiming that the scan measured low iron. Lower-observed-risk education explicitly states that a visual result does not confirm normal iron status. The UI links to the authoritative sources and labels all content as general education rather than a personalized diet or treatment plan.

## Multimodal research preparation

`MLTraining/scripts/train_multimodal_suite.py` defines three independent engineering-fixture exports because eye, nail, and tongue imagery have different acquisition and preprocessing contracts. Every package must retain its own manifest, calibrated probability, locked threshold, model version, and preprocessing version. The script does not create a combined model and refuses image-level random splitting; participant groups must remain disjoint across train, validation, and test.

The uncertainty-enabled exports train MobileNetV3-Small with dropout probability `0.2` and evaluate 30 deterministic Bernoulli masks at the classifier head inside one Core ML prediction. Outputs are the mean raw proxy logit, mean calibrated proxy probability, and probability standard deviation. This fixed-mask ensemble preserves deterministic parity across Swift and Python; it is not equivalent to obtaining a new random dropout sample on each Core ML call. Repeating the package ten times would return identical values and is therefore prohibited as a false stochastic estimate.

The Eye step loads `IronScanEye_Clinical.mlpackage` and `eye_clinical_manifest.json`. `MultiTissueInferenceActor` runs `VNDetectFaceLandmarksRequest` off `MainActor`, selects the detected eye nearest the frame center, converts the lower 25 percent of its landmark bounds into an sRGB BGRA crop, and then applies the manifest resize contract. Live preview frames are serialized by the actor and expose a lighting/eyelid warning when the package's locked predictive standard deviation is exceeded. Missing physical landmarks still reject capture. Ensemble uncertainty is retained in the captured output so fusion can down-weight or exclude only the affected tissue instead of discarding otherwise usable sites.

`TriangulationEngine` is a pure `Sendable` Swift component. It verifies all model and preprocessing versions before fusion and requires uncertainty from the fixed-mask ensemble. For every usable tissue it computes `1 / (variance + 0.001)`, normalizes those inverse-variance weights, and applies explicitly versioned research priority multipliers of `1.2` for eye and `0.9` for nail and tongue. The final bounded optical score is the sum of normalized weight × model probability × priority multiplier. A tissue variance over `0.15` or a rejected image-quality result excludes only that tissue and produces a re-scan flag; at least two usable tissues are required for a combined result. These constants and thresholds are unvalidated research assumptions, not clinical weights.

`IDARiskEngine` receives the already-finalized optical result and a local `ScreeningIntakeSnapshot`. It never modifies individual Core ML outputs. Fatigue, cold-hands, and plant-based-diet selections can raise follow-up priority for the presentation layer; biological sex is displayed but is not scored because no validated cohort-specific adjustment exists. The context layer emits only `Lower observed risk`, `Possible anemia risk`, or `Unable to assess`, and never estimates hemoglobin, ferritin, or iron concentration.

After one-time research consent, debug builds expose a three-step educational demo with a persistent research-prototype footer. `MultiTissueInferenceActor` loads and validates the eye, nail, and tongue engineering fixtures once, prepares each frame according to its own manifest, and calls Core ML directly. `MultiScanHubView` captures eye, nail, and tongue frames sequentially before supplying all three outputs to an explicit versioned prototype fusion configuration. Release interpretation remains blocked: eye and nail evaluation uses synthetic appearance-similarity groups rather than verified participant identities, physical-device performance and acquisition validity are unverified, and none of these proxy models measures hemoglobin, ferritin, iron status, or a clinical condition.
